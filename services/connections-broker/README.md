# Connections broker process

Run the compiled application artifact's broker entry point under a dedicated non-root OS user, different from Studio. The broker can read its private config, vault directory, 32-byte AES key and a dedicated HMAC authentication key. Studio receives a separate copy of the HMAC key and cannot read the vault or AES key. File modes are 0700 for vault and 0600 for configuration/keys. Startup verifies ownership/modes, rejects equal identities and keys, and rejects ambient Studio credential environment variables.

The implementation entry point is `scripts/connections-broker.mjs` with `node --import tsx`. Supply `serve`, `check-config`, or `enroll`, then an absolute broker-owned JSON config file. `enroll` additionally takes account ID, Work/Personal space and flow ID; its token comes exclusively from stdin. It has no browser/token HTTP endpoint, never prints credentials, and seals enrollment until the user claims it from authenticated Studio.

Use `brokerConfigurationSchema` as the exact configuration format. No provider is enabled by default. Configure only independently admitted providers and exact reviewed resource/tool/destination inventories. OAuth profiles currently support GitHub user authorization and Google's OpenID-backed services; GitHub installation credentials and unverified provider tenant profiles remain unavailable. Static-token identity profiles are deliberately limited; unsupported profiles fail instead of accepting an operator's claimed subject.

The loopback broker and loopback Studio control endpoint authenticate every private request with bounded timestamp/nonces and HMAC. Expose only `/oauth/callback/<enabled-provider>` through a reviewed HTTPS reverse proxy at the pinned registered callback URL. Never expose private `/v1/*` paths, use public cleartext HTTP, proxy provider responses, add request-body logs or enable generic egress. Consult `docs/connections/BROKER_OPERATIONS.md` for operational limits, revocation and release evidence.
