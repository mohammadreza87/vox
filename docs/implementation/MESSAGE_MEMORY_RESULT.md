## User flow / مسیر کاربر

EN: Conversation exposes **Review this text for memory** beside completed own text lines only. Selecting it shows the exact text and current private Work/Personal scope. Nothing is exported until **Preview private claims**. Only that text reaches the configured qualified AI provider; no assistant text, image, audio, history, directory or other notes are read. The model proposes zero to three claims. Check their attribution, dates and uncertainty, then explicitly save all proposed claims or discard. Empty previews cannot save. Saved notes are labelled **user-reviewed claims, not independently verified**, expire under the existing 90-day note policy, and can be inspected/deleted in Privacy. Closing/scope changes discard source selection and preview; late replies never enter the new scope. Cancellation before commit saves nothing; an already completed save requires deletion in Privacy.

FA: کنار پیام‌های متنیِ ارسال‌شدهٔ خود در گفتگو، «بررسی این متن برای حافظه» دیده می‌شود. انتخاب آن، متن دقیق و فضای خصوصی کاری یا شخصی فعلی را نشان می‌دهد. تا انتخاب «پیش‌نمایش ادعاهای خصوصی» چیزی ارسال نمی‌شود. فقط همان متن به ارائه‌دهندهٔ واجد کنترل می‌رود؛ متن عامل، تصویر، صوت، تاریخچه، فهرست افراد و یادداشت‌های دیگر خوانده نمی‌شوند. مدل صفر تا سه ادعا پیشنهاد می‌دهد. انتساب، تاریخ و عدم قطعیت را بررسی و سپس همهٔ پیشنهادها را صریحاً ذخیره کنید یا کنار بگذارید. پیش‌نمایش خالی ذخیره نمی‌شود. یادداشت‌ها «ادعای بررسی‌شدهٔ کاربر، بدون تأیید مستقل» هستند، طبق سیاست فعلی پس از ۹۰ روز منقضی می‌شوند و در حریم خصوصی قابل مشاهده و حذف‌اند. بستن یا تغییر فضا، انتخاب و پیش‌نمایش را پاک می‌کند؛ پاسخ دیرهنگام وارد فضای تازه نمی‌شود. لغو پیش از ثبت چیزی ذخیره نمی‌کند؛ ذخیرهٔ کامل‌شده باید در حریم خصوصی حذف شود.

## Contract and authority / قرارداد و اختیار

- `POST /api/studio/adaptive/message-memory/preview`: signed Telegram identity/membership, same-origin JSON, current confirmed account/core capability, exact allowed agent/space. Strict input `{space,agentId,locale,text}`; original source whitespace is preserved, at most 4,096 characters. Preview is an explicit `explicit.memory_request`, not an automatic-memory grant. Server accepts user-provided content, **never proof of prior authorship or factual truth**.
- Only the configured qualified Anthropic fetch-fenced adapter is supported, in the existing single-process FILE topology. Ten-second inference deadline, cancellation signal, zero hidden retries, bounded complete output: zero–three unique claims, each at most 1,000 characters and total at most 3,000. Provider truncation/malformed/oversized or extra-authority fields fail closed. Model output cannot select ACLs, scopes or sharing.
- HMAC receipt version 1 binds nonce, account/person, current binding/core/Studio authority, exact agent/space, exact selected-text hash and ordered claim hashes. Expiry is at most two minutes, bounded by current authority expiry. Selected source, source hash, prompts, draft and receipt remain ephemeral. Durable events retain nonce, scope/accepted-text fingerprint and result IDs only; no separate raw-source payload/hash or retry queue is persisted.
- `POST .../message-memory/accept`: exact claims/hash/receipt only; whitespace edits and wrong account/space/agent fail. All notes save atomically with FILE lock, fresh Studio authority and clock after temporary fsync, followed immediately by synchronous rename. HTTP delivery is rechecked after loading its response. Abort before commit rejects. Accepted nonce replay returns the same IDs; deleting any accepted note cannot recreate it by replay. Unsupported snapshots/providers fail closed without disabling ordinary notes.
- Stored rows add only optional server-authored `origin:'user_reviewed_claim'`. Ordinary note requests cannot set it. Private retrieval still requires existing personalization consent and exact agent grant; claims and summary descendants retain the unverified label in model context, within existing whole-record budgets. Existing lineage/deletion/expiry rules apply. No optional consent, automatic collection hook, Decisions call, final-turn learning hook, shared publication or notification is added.

FA: درخواست‌ها به هویت امضاشده، عضویت و اختیار فعلی، مبدأ یکسان و عامل و فضای دقیق وابسته‌اند. این یک درخواست صریح حافظه است و هیچ رضایت حافظهٔ خودکاری ایجاد نمی‌کند. متن، دادهٔ ارائه‌شدهٔ کاربر است و اثبات نویسندگی قبلی یا حقیقت نیست. منبع حداکثر ۴۰۹۶ نویسه دارد و فاصله‌های آن عیناً حفظ می‌شود. مهلت استنتاج ده ثانیه و بازآزمایی پنهان صفر است؛ خروجی حداکثر سه ادعای یکتا، هرکدام هزار و در مجموع سه هزار نویسه دارد. رسید امضاشده حداکثر دو دقیقه، اختیار و فضای دقیق، هش متن و ادعاهای مرتب را مقید می‌کند. منبع، هش آن، پرامپت، پیش‌نویس و رسید پایدار نمی‌شوند. ذخیرهٔ همهٔ ادعاها زیر قفل فایل و آخرین بررسی هم‌زمان اختیار و ساعت اتمی است؛ تکرار رسید، ردیف تازه نمی‌سازد و حذف را برنمی‌گرداند. فیلد اختیاری مبدأ فقط روی سرور ساخته می‌شود. استفاده در بازیابی همچنان رضایت شخصی‌سازی و مجوز عامل را می‌خواهد؛ ادعاها و خلاصه‌های مشتق، برچسب عدم تأیید مستقل دارند. رضایت رابطهٔ `optional.auto_memory`، هوک یادگیری، Decisions، اشتراک‌گذاری و اعلان تغییری نمی‌کنند.

## Rollback / بازگشت نسخه

EN: `message-memory/rollback.ts` defaults to dry-run, for one explicit absolute FILE directory/account only. Apply requires stopped producers and matching current-content SHA under the account lock. It strips **only additive origin metadata**, preserving accepted note text, IDs, revisions, expiry, valid summary descendants, current rights and all events/tombstones, restoring the strict `08ca4f2` shape. Those notes were never independently verified; metadata removal does not confer verification. It never restores an old account backup or scans accounts. No production rollback was run.

FA: ابزار بازگشت فقط برای یک پوشهٔ مطلق فایل و یک حساب مشخص، به‌طور پیش‌فرض بررسی بدون تغییر انجام می‌دهد. اعمال، توقف تولیدکننده و هش منطبق زیر قفل را لازم دارد. فقط فرادادهٔ افزودهٔ مبدأ حذف می‌شود؛ متن یادداشت‌های پذیرفته‌شده، شناسه، نسخه، انقضا، خلاصه‌های معتبر مشتق، حقوق فعلی و رویدادها و سابقهٔ حذف باقی می‌مانند و شکل سخت‌گیرانهٔ نسخهٔ `08ca4f2` برمی‌گردد. این یادداشت‌ها هرگز مستقلاً تأیید نشده‌اند و حذف برچسب، تأییدی ایجاد نمی‌کند. پشتیبان قدیمی جایگزین یا حساب‌ها پیمایش نمی‌شوند. بازگشت تولید اجرا نشده است.
