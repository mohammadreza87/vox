# Protected evaluation protocol / پروتکل ارزیابی محافظت‌شده

VOX-007 with bounded VOX-044/046 integration, 20 October 2026. New implementation candidate awaiting independent acceptance. The only executable adapter is deterministic and synthetic. This protocol neither authorizes private data/provider calls nor establishes production isolation, calibrated language quality or statistically significant improvement. Read with [improvement workflow](../../src/lib/adaptive/improvement/README.md), [research](../SELF_DEVELOPMENT_RESEARCH.md), [memory strategy](../AGENT_MEMORY_STRATEGY.md) and [QA/release](QA_AND_RELEASE.md).

## Frozen inputs and separation

`src/lib/adaptive/improvement/evaluation/contracts.ts` defines strict, bounded version-1 schemas. `syntheticProtocolInputs()` is a complete runnable manifest/corpus template, not protected production data or a production policy. It has separate optimization, validation and final collections, each with six fictional cases. Every case carries hashed task, person, conversation and optional exact-group IDs, event time, locale, scenario, bounded fictional input and deterministic expected action. Hashes remain restricted metadata, not anonymity claims.

`validateEvaluationInputs` checks exact corpus and partition digests, counts, case uniqueness, disjoint task/person/group/conversation IDs between all partitions, and nonoverlapping forward time windows. Cases must lie in their partition's half-open time interval. A different case ID cannot conceal a reused person, group, conversation or task. This version supports a strict new-person/new-group generalization split; known-person longitudinal evaluation needs a separately reviewed split policy. Group IDs must identify the canonical exact audience/container, not one DM or a guessed speaker. The caller owns correct source identity; a hash cannot verify an audience.

The final collection must cover cancellation, active continuation, revoked sharing, unknown identity, verified notification outcome and unknown notification outcome, plus English, Persian and mixed language. Scenario labels must match deterministic policy. A notification with unknown delivery remains an unavailable task outcome even when the correct decision is to report uncertainty. Neither HTTP success nor provider acceptance becomes verified delivery. These are synthetic policy exercises, not physical playback/notification proof.

The manifest binds corpus/partition digests, judge/calibration and scoring digests, runner/adapter digests, split metadata, review/expiry, explicit retention reference/deadline, required coverage, a minimum independent-unit count and fixed budgets. No numeric production retention term is supplied. Statistics are explicitly descriptive only, at person or exact-group units; population/causal claims and automatic model selection are unauthorized. Minimum units and paired gains are predeclared gates, not a confidence interval, power calculation or representative study.

`evaluationProtocolDigest(manifest)` commits to the full manifest digest plus minimized split/coverage/count/review metadata, component digests, retention deadline and budget. This redundant commitment lets receipt validation detect altered corpus, judge, scoring, split or budget fields without copying protected scoring configuration into the workflow. Runner identity hashes its execution/aggregation/input-validation/commitment functions, semantic schema refinements and JSON schema shapes. Adapter identity hashes the fixed adapter implementation. Build/transpilation changes may change these digests; freeze them for the exact evaluator artifact and create a new reviewed protocol rather than silently rebinding an existing candidate.

`optimizerProjection` emits only a synthetic optimization capability: protocol digest, purpose/evidence literals, optimization case budget and a defensive copy of optimization cases. Validation/final examples, judge/calibration configuration and scoring thresholds are absent. `optimizeProtocolRouting` accepts only that strict capability and the baseline artifact plus a bounded candidate limit; it converts only optimization cancellation/active cases into the existing fixed-budget routing search. The evaluator receives protected inputs; the optimizer must never receive the original arguments used to produce its projection. Aggregate protocol digest and optimization case count are the only manifest metadata in the capability.

This is a code-level data projection. It is **not** filesystem/process/IAM isolation. The host adapter object is evaluator-trusted code; supplying a digest string does not authenticate arbitrary function bytes. A production runner must load the reviewed pinned adapter/artifact under separate evaluator credentials, deny optimizer/author access to protected corpus/judge/scoring files and signing keys, and protect the registry/checkpoint. Separate local objects, TypeScript interfaces, synthetic role keys or a shared repository cannot provide that boundary. Never mount protected examples or scoring into an optimizer job. External service accounts, storage ACLs, evaluator deployment ownership and an append-only external checkpoint remain release gates.

## Paired execution and denominators

`runEvaluation` validates the frozen candidate/artifact/protocol binding before adapters receive an input. Each final case runs baseline then candidate at matched conditions. The adapter gets only the arm's inert routing artifact and locale/fictional input, not expected labels, partition metadata, scoring or case identity. There is no model or provider dependency. The built-in adapter changes cancellation routing; revoked/unknown identity and notification uncertainty remain fixed policy exercises. It does not claim general model-quality coverage.

Budgets cap final cases (128), calls (256), reported total cost including discarded work, summed reported latency and wall time (at most 60 seconds). Execution is sequential, propagates cancellation, bounds waiting with an AbortSignal/timeout, ignores late results and leaves unexecuted rows explicitly skipped. Trusted adapters must honor abort to stop their own work; ignoring a late promise does not terminate arbitrary external code. No blind retry or additional provider call is made. Reported resource caps are checked after each result; they cannot prevent an unauthorized external adapter from spending. No paid adapter is authorized by this API or synthetic provenance.

Every arm retains the full assigned denominator. Complete, invalid, refused, unavailable and skipped counts must sum to assigned. Malformed output becomes invalid; thrown/timed-out work becomes unavailable. Coverage is complete/assigned, verified task success is successful/assigned, and quality is score/assigned with zero for missing/unsafe/incorrect results. Refusal, missing outcomes and dropped telemetry cannot improve these rates by disappearing. An unknown task outcome never counts as success.

Latency p50/p95 use the nearest-rank definition and are unavailable (`null`) if any assigned latency is missing. Total cost includes regular plus discarded cost for both arms; per-success cost is total/successes and unavailable when any cost is missing or successes are zero. These values are reported by the synthetic adapter, not measured provider billing or user-perceived latency. Zero cost is a known scripted zero, distinct from unavailable. Unknown judge scores make the run incomplete; low scores fail the predeclared quality gate. A judge's favorable score cannot override a wrong deterministic action, revoked/unknown identity disclosure, unverified notification claim, or privacy failure.

Passing requires full baseline/candidate coverage and metric availability, zero candidate deterministic/privacy failures, the reviewed verified-success rate and paired gain, minimum quality, latency and per-success cost gates, and all budgets. Failed/incomplete results remain signed minimized evidence. Clock regression or protocol expiry during awaited work produces no eligible result. Human calibration, real task outcomes, experimental randomization/power/multiple-testing rules and real cost/latency qualification remain unavailable.

## Signed workflow and promotion continuity

1. Freeze the protocol digest in the server proposal before optimization/candidate registration. The author signs the candidate with the same `evaluationProtocolDigest`; omitting or changing it relative to the proposal is rejected.
2. Sign a minimized `evaluation_protocol_reservation` with the independently configured evaluator key. `evaluateReservedProtocol` commits it through `reserveEvaluationProtocol` before any protected adapter call. It binds the frozen protocol/candidate/base and consumes the final-partition digest once. Exact replay returns an already-reserved result and executes no adapter; changed replay is rejected. A crash or lost response burns the attempt rather than permitting a second final run. Then run the protected synthetic preflight under that evaluator key. Sign its minimized receipt with purpose `evaluation_protocol`. It binds exact candidate/base/artifact, legacy Docker dataset/evaluator/promotion-policy versions, manifest/split/coverage/corpus/judge/scoring/runner/adapter digests, budgets, aggregate metrics and current expiry. It stores no examples, text, prompts, judge configuration or logs.
3. `attachEvaluationProtocol` verifies role/signature, binding, budget and expiry and requires the exact earlier evaluator reservation. The final-partition digest was already consumed before execution, including attempts that fail, remain incomplete or crash. Exact operation replay is idempotent; changed replay is rejected. A later candidate cannot reuse this protected final collection for selection. Refresh requires a genuinely new reviewed final dataset; changing metadata cannot establish semantic novelty by itself.
4. The existing protected Docker final evaluation is still required. Its fixed evaluator program and existing protected fixtures were not changed. `bindProtocolFinalEvaluation` verifies the independently signed preflight and existing Docker envelope, then re-signs the final receipt with the protocol digest and exact companion-envelope digest. It does not execute Docker or invent a Docker result.
5. `attachEvaluation` refuses the legacy-only path for protocol-bound candidates, requires the stored passed/current companion, the same evaluator key, exact companion digest and matching candidate/version receipts. Legacy candidates without a declared protocol retain their existing behavior. A pure promotion caller must supply the new trusted `verifyProtocol` callback for a protocol-bound candidate; its old receipt callback alone cannot qualify it.
6. Existing human approval binds the complete signed final envelope, including the companion digest. Readiness rechecks the companion signature/current protocol and human approval. Readiness is a local review result, never a deployment or permission grant.

The synthetic integration test genuinely exercises optimization, Ed25519 roles, durable workflow/restart, companion binding, old-path refusal, human review and local readiness. Its existing Docker envelope is explicitly a synthetic signed host fixture; no container execution is claimed by that test. Actual Docker qualification and protected service deployment remain separate. Existing Docker tests run only with the separately configured pinned local image; skipped checks stay visible.

The additive candidate/receipt/proposal fields are optional for old records. Old binaries will reject or fail to qualify new protocol-bound candidates; preserve the current workflow/audit directory and protocol-use markers during rollback. Do not remove protocol fields/consumption records or restore an older audit history to obtain legacy readiness. This workflow stores only minimized receipts/digests; protected corpus bytes remain evaluator-owned. Expired protocol receipts block readiness, but this patch adds no audit deletion/scheduler or production retention enforcement. Retention/storage retirement must preserve replay and final-set consumption evidence under reviewed operations.

Independent acceptance must evaluate the exact committed candidate. Author tests are not independent acceptance. No live provider/user data, production credentials, messages, configuration, deployment, protected fixture edits or blocked export harness were used.

## فارسی

این نامزد VOX-007 با بخش محدودی از VOX-044/046 هنوز به پذیرش مستقل نیاز دارد. تنها آداپتور اجرایی قطعی و مصنوعی است؛ اجرای ارائه‌دهنده، دادهٔ کاربر، استقرار یا ادعای جداسازی واقعی مجاز نشده است.

فهرست نسخه‌دار، پیکره و بخش‌های آموزش بهینه‌ساز، اعتبارسنجی و نهایی را با هش، زمان، تعداد و سیاست بازبینی/نگهداری متصل می‌کند. شناسه‌های کار، شخص، گروه و مکالمه میان بخش‌ها نباید مشترک باشند و زمان‌ها باید رو به جلو و جدا باشند. بخش نهایی باید فارسی، انگلیسی و زبان ترکیبی، لغو، ادامهٔ فعال، اشتراک لغوشده، هویت نامشخص و نتیجهٔ اعلان تأییدشده و نامشخص را پوشش دهد. نتیجهٔ نامشخص اعلان هرگز موفقیت کاربر فرض نمی‌شود.

بهینه‌ساز فقط نسخهٔ محدودِ نمونه‌های آموزش را می‌گیرد، نه نمونه‌های اعتبارسنجی/نهایی یا تنظیمات داور و امتیازدهی. این مرز نرم‌افزاری به‌تنهایی جداسازی فرایند، فایل یا IAM نیست. حساب‌های سرویس، مجوزهای مستقل ذخیره‌سازی، مالکیت آداپتور و کلید داور و حفاظت بیرونی دفتر همچنان گیت انتشار هستند.

هر نمونه برای خط پایه و نامزد اجرا می‌شود. همهٔ نمونه‌های تخصیص‌یافته در مخرج می‌مانند؛ نامعتبر، ردشده، ناموجود و اجرا‌نشده حذف نمی‌شوند تا نرخ‌ها بهتر دیده شوند. هزینهٔ کار دورریخته‌شده نیز شمرده می‌شود. نبود هزینه، زمان یا امتیاز داور مانع قبول است. شکست قطعی اختیار یا حریم خصوصی با امتیاز مثبت داور جبران نمی‌شود. بودجهٔ نمونه، فراخوانی، هزینه و زمان ثابت است و لغو یا پاسخ دیرهنگام باعث تکرار کور نمی‌شود. آمار فقط توصیفی و مصنوعی است؛ تعمیم یا بهبود معنادار آماری ادعا نمی‌شود.

هش پروتکل پیش از ثبت نامزد در پیشنهاد ثابت می‌شود. رسید حداقلی با کلید مستقل داور به نامزد، خط پایه، پیکره، داور، امتیازدهی، زمان‌بندی تقسیم و بودجه متصل است. بخش نهایی پیش از اولین فراخوانی آداپتور با رزرو امضاشده در دفتر مصرف می‌شود؛ پاسخ گم‌شده، شکست یا توقف فرایند اجازهٔ اجرای دوباره نمی‌دهد. مسیر قدیمی رسید به‌تنهایی برای نامزد وابسته به پروتکل پذیرفته نیست. ارزیابی محافظت‌شدهٔ Docker همچنان جداگانه لازم است؛ رسید انسان کل پاکت ارزیابی نهایی و هش رسید پروتکل را تأیید می‌کند. آزمون محلی از رسید Docker ساختگیِ صریح استفاده می‌کند و اجرای واقعی کانتینر را ادعا نمی‌کند.

نامزدهای قدیمی بدون این فیلد رفتار قبلی خود را حفظ می‌کنند. بازگشت نسخه نباید فیلدهای پروتکل، نشانگر مصرف مجموعهٔ نهایی یا دفتر فعلی را حذف کند. ارزیابی انسانی کالیبره، کیفیت واقعی زبان، مجوزهای بیرونی، دستگاه، CI و انتشار همچنان نیازمند شواهد جداگانه‌اند.
