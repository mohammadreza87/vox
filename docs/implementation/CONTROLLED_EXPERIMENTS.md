# Controlled response presentation experiments

VOX-029 / VOX-047 local implementation candidate, 20 October 2026. This extends the Studio path under the [architecture](ARCHITECTURE.md) and [QA/release rules](QA_AND_RELEASE.md). An implementation, reviewed configuration reference or local operator command is not independent acceptance or production authorization.

The first runtime effect is a fixed text presentation density: control `comfortable`, candidate `compact`. It changes reply typography in the conversation panel. It does not alter generated text, model input, retrieval, grants, consent, tool actions, notifications or canonical memory. There is no free-form candidate payload. The runtime has no model dependency.

## Configuration and lifecycle

The optional runtime is default off. Root integration must explicitly select a supported persistent file runtime; an empty ledger contains no enabled experiment. `install` validates a strict reviewed configuration and always creates phase `off`. Activation must follow `off → offline → shadow → pilot`. Offline/shadow evidence references, distinct owner/reviewer, artifact digests, assignment version/salt, enrollment fraction, dates, approved retention policy and stopping rules are required. These references are operator attestations; the module does not fabricate, execute or cryptographically verify independent evaluations. The release owner must validate their exact artifacts before using the operator interface.

`shadow` computes only isolated content-free presentation records; it returns no client effect and records no exposure. `pilot` may return a scoped presentation receipt. Multiple simultaneously eligible experiments for the same assignment kind fail closed. Assignment/exposure limits and operator-reported presentation failures are predeclared; reaching a stopping rule kills the version. No statistical result automatically promotes a candidate. The configured readability success metric remains a study/readout requirement; this module does not infer readability, task success, causality or winning variants.

`ControlledExperimentService` is server/operator-only. No client route installs, promotes, changes a variant, chooses a unit or issues a kill. The HTTP endpoint accepts only `{space, agentId, receipt}` after Telegram authentication, rate limits, same-origin validation and bounded strict JSON validation.

## Assignment, consumption and exposure

Private assignment uses tenant + Work/Personal + verified person. Shared assignment uses tenant + Work/Personal + canonical container ID + kind + sorted unique exact recipient set. Conversation ID and agent ID are absent. Separate DMs using the same canonical selected-recipient container receive the same assignment. Membership changes form a different unit. The controller supports shared assignments, but this candidate's production integration surface is **private Studio text only**; its shared-container tests are local contract evidence, not a shipped shared UI.

The salt, experiment ID, assignment version and unit deterministically select control/candidate. Assignments cannot be edited in place. Derivations are separately keyed by assignment, source reference/revision, current server authority and configuration revision. The only derived value is presentation density; raw conversation text is never accepted or retained. Candidate and control records stay in this experiment namespace. The controller never reads or mutates canonical memories, source records, explicit preferences, access grants or their tombstones.

`StudioExperimentRuntime.prepare` derives private identity from current server controls. It requires confirmed identity, current core/analytics/personalization capability eligibility, both analytics and personalization purpose consent, exact agent grant, an active approved Studio member, accessible/unblocked active agent, and no product personalization pause. It checks scope/permission/expiry again in the storage publication fence and after preparation. Unsupported or busy authority/storage suppresses the optional effect. `current` is the final synchronous response-publication check; callers must invoke it immediately before returning metadata.

Preparing a response does not count as exposure. ConversationPanel must apply density only to that response and acknowledge after committed, connected, visible text. The controller checks current authority/configuration/source tombstones again before appending `text_rendered`, explicitly `client_unverified`. A duplicate receipt produces one exposure. Client reports cannot prove that a human read or understood a response. If acknowledgement returns neither `recorded` nor `duplicate`, the panel restores comfortable density.

## Kill, rollback, rights and retention

The file ledger uses fresh uncached reads and synchronous serialized transactions. The operational kill bound is the **next server preparation, final response fence or exposure acknowledgement**, including another process using the same directory. Already rendered browser typography is not continuously polled and cannot be retroactively unrendered. A failed acknowledgement restores baseline presentation; a newly prepared response receives no effect after kill.

Kill atomically marks the version terminal, invalidates receipts and quarantines every derived row for that experiment. Purge removes its derived rows. Version kill tombstones remain; neither replay, reinstall nor lifecycle transition revives that version. Reverting application code must preserve this ledger and its tombstones. Never restore an old ledger/account backup over current deletion or suppression state. Canonical source and deletion tombstones are untouched by either rollback mode.

`deleteSource` removes that source's experimental derivations/exposures and retains a minimal unit/source deletion marker that blocks all later source revisions, including a newly installed experiment. `purgeScope` removes all assignments, derivations and exposures for the exact private person/space or shared unit. Its minimal markers suppress previously assigned experiment versions. After explicit consent is granted again, a new independently reviewed experiment ID/version can enroll; the old version cannot refill purged records. Markers are never evicted to admit new enrollment. Capacity failure preserves existing state and suppresses optional work. Marker retirement requires a separately designed safe store retirement/replay policy; none is provided here.

Root integration must register `reconcileAccount` after canonical account commits and maintenance/read retries. It reads direct current metadata, without reentering a canonical write. Withdrawal/expiry/unconfirmed identity and binding/permission/store epoch changes purge affected records. Pause suspends use and preserves otherwise authorized retention. No-op matching/empty reconciliation is read-only. Separate stores are **not atomic**: a canonical withdrawal can commit before experimental purge fails; immediate runtime authority denies use and the post-commit reconciler must retry on the next account read/maintenance operation. Physical purge latency is therefore bounded by successful reconciliation/maintenance, not the canonical transaction. An unavailable reconciler must remain visible to operations.

Retention is an explicit reviewed `retention.policyVersion`, `approvalReference` and absolute `retainUntil`; this implementation invents no production retention duration. Derived effects expire at the earlier of authority/configuration expiry. Assignment/exposure records expire at reviewed `retainUntil`, which must be at least the study's configuration expiry. Expiry/retention sweeps run on controller interactions and reconciliation; existing scheduled account maintenance must invoke reconciliation for idle accounts. With no maintenance/traffic, this library alone does not promise physical deletion at a wall-clock deadline. Content-free kill/source/scope suppression markers outlive the study so delayed work cannot resurrect it.

The ledger persists the maximum observed service time. Once a running version is observed expired it is killed; restarting with an earlier clock does not revive it. The private directory/ledger reject application symlinks, hard-linked/nonprivate records, oversized input and unsafe lineage. Descriptor reads are bounded to 2 MB before JSON parsing; writes use private temporary files, fsync and atomic rename under a cross-process lock. A crash lock fails closed and needs operator inspection before removal. Fifty definitions, 1,000 assignments, 2,000 derived rows, 2,000 exposures and 3,000 reserved tombstones cap the store; there is no automatic eviction of deletion evidence.

The authenticated account export can use `prepareScopeExport` and append its minimized data to the existing export. Its `revalidate()` must run after serialization and immediately before publication, alongside requester and canonical export fences. Export includes study/variant/times/density/state, not internal unit/authority hashes, source references or effect receipts. Management export/purge derives the account's stable scope without requiring optional consent or an active profile binding; the caller must authenticate the exact account.

## Local operator interface and evidence

Only run against a specifically authorized local directory. The script does not discover credentials, select a production target, send messages or deploy. It outputs status/counts, never the ledger/configuration body. Use a reviewed strict JSON input matching `experimentConfigSchema`; synthetic examples live in `src/lib/adaptive/experiments/test-fixtures.ts`.

```sh
node --import tsx scripts/studio-experiments.ts /absolute/local/ledger install /absolute/reviewed-config.json
node --import tsx scripts/studio-experiments.ts /absolute/local/ledger advance study-id 1 offline
node --import tsx scripts/studio-experiments.ts /absolute/local/ledger advance study-id 2 shadow
node --import tsx scripts/studio-experiments.ts /absolute/local/ledger advance study-id 3 pilot
node --import tsx scripts/studio-experiments.ts /absolute/local/ledger kill study-id 4 quarantine
node --import tsx scripts/studio-experiments.ts /absolute/local/ledger kill study-id 5 purge
node --import tsx scripts/studio-experiments.ts /absolute/local/ledger sweep
```

Local checks: `vitest run src/lib/adaptive/experiments`, scoped ESLint, and TypeScript. Synthetic fixtures exercise stable cross-session/private/shared assignment, isolated control/candidate lineage, explicit exposure/idempotence, review/lifecycle rejection, authority changes, kill/quarantine/purge, delayed source replay, withdrawal reconciliation, minimized export invalidation, stopping rules, approved retention, restart/clock rollback, bounded unsafe-file rejection and actual authenticated HTTP exposure handling. Independent QA, composed Studio/UI tests, CI, production approval/configuration, live provider behavior, physical device validation and shared-runtime enrollment remain separate gates owned by the lead/evaluator. No production configuration, provider generation, messages or deployment were performed for this slice.
