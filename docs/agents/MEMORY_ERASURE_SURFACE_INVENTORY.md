## Named operation and completeness boundary

The selected operation is **original-FILE canonical memory-account erasure**: one server-authenticated `telegram-account:<id>` canonical account, both Work and Personal, every agent's rows inside that account. The physical target is the server-derived `adaptive/<sha256(accountId)>.json`, including its eligible registered transient files. It includes canonical content, derived state, archive state/pointers and assistant-delivery controls. The root's format/time/ownership markers are operational controls and survive this per-account operation.

This operation does not delete a Vox/Telegram account, persona, the whole Studio directory, all chats or all local personal data. A source record in another store may remain physically present. Before ER1 activation, its use as canonical/private conversation context, extraction input or restoration authority must be blocked unless it has independently qualified current-incarnation lineage. Unknown legacy lineage is excluded. User-visible own chat history is a separate retention/display decision and cannot silently become agent context again.
