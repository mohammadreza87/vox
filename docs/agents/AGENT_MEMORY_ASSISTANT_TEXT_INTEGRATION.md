## 1. Deliverable and scope

Wire the actual persistent poller → `handleAgentUpdate` → `PersonaGateway` → dedicated nonretrying `sendMessage` POST path to ADP1 and canonical ARC controls. The bounded effect is one ordinary initial plain-text reply in a verified owner's own private Work DM, with original canonical FILE, actual local `StudioStore`, compact privacy and a selected text reply format. The model/generation path is the existing one; this increment adds no model calls. Synthetic tests exercise this real composition with injected model/HTTP responses and real synthetic FILE documents. Another unused protocol/adapter is not an acceptable substitute.

`STUDIO_ASSISTANT_TEXT_DELIVERY` accepts only absent/empty/`0`/`1`, default off. On requires `STUDIO_BOTS=1`, FILE Studio/original FILE adaptive format, no public webhook URL/serverless environment, supported synchronous committed stores, explicit key configuration and the topology condition in section6. The composition attaches the real integration service and poller seam; it never enrolls an account on startup or message arrival. No real producer is enabled by this contract. A flag, ARC permission or archive enrollment is not delivery enrollment or legal qualification.

The qualified selector is scoped. A known ATI1 enrollment row, enabled or disabled, selects that bot/owner/agent Work relationship; unavailable/disabled/stale states refuse internally with zero ordinary reply fallback. A never-enrolled relationship keeps its existing unqualified behavior and receives no delivery-tracking guarantee. Before any ordinary legacy fallback on an account that already has ARC controls, check the authenticated original source against surviving account/stream replay floors and retained effect keys: an old/fenced/already-claimed source refuses0POST, even without an enrollment row. This does not create controls, refresh dates or block a fresh unrelated source above the barriers. Missing/unreadable current controls cannot be interpreted as known safe absence. The format marker conveys reader admission only and cannot select unrelated people. Switch-off pauses enrolled relationships, never routes them back to legacy. Switch-on can permit fresh sources under an existing enabled enrollment, but cannot reverse explicit disable or resume an old attempt. Normal restart preserves durable enrollment and closes interrupted sends as unknown. No process-session enrollment or new consent on every restart is introduced.

Voice/transcripts, voice/image/media inputs, commands/control responses, groups/public outsiders/guests, pet/Mini App, proactive relationships, reminders and manager-bot replies remain outside this effect. Their existing callers are not migrated or described as qualified. Selected owner plaintext whose current format is voice is refused by this path, with no text/voice fallback; another modality needs its own contract. On the selected path suppress `sendChatAction`, so admitted success has exactly one total Telegram POST. Refusal/preflight happens before typing, reply generation or legacy preambles wherever the existing format can be determined deterministically. Existing authorized context/model work is not repeated to obtain qualification.

No assistant text, generated text, wire bytes, raw response, provider exception, key or token enters the received-user archive, legacy history, durable retry, diagnostics or observation payload. Archive/snapshot horizons and activation switches stay unchanged. No old history is revived or backfilled and no two-sided recall claim follows.

This narrowly supersedes ADP1/ARC1 restrictions against runtime consumers only for ATI1's named integration. ADP1 codec, identity, exact wire, reducer and certainty semantics stay unchanged. ARC1 v1 continues reading/safety/rights support; section2 adds the minimum separately versioned enrollment authority.
