## Diagnosis and scope

`scanPetCare` in `scripts/studio-adaptive-compatibility.mjs:651–683` admits `.epochs/` and agent JSON files only. Current FILE runtime (`src/lib/studio/runtime.ts:287`) already wires all four pet stores. Its play/growth/check-in writers create three fixed subdirectories under the same pet root. The unchanged scanner consequently refuses a legitimate known directory at its filename check. This is an existing pet/admission mismatch, not a new ARC1 control failure. Root's metadata-only release classification reports real nonlink play/growth directories, checkins absent and no unexpected root names; it supplies no record-validation evidence.

**Implement only a strict read-only extension of this release helper and its exported capabilities.** No writer/schema migration, permission, retention, feature flag, epoch, secret, pet behavior or ARC1 source change. No deletion/renaming/ignoring existing pet state to unblock installation. All accepted ARC1 paths except the explicitly assigned shared helper remain byte-identical. Root owns documentation and final release/artifact decisions; independent QA owns all new fixtures/oracles.

## Fixed layout and capabilities

Preserve current root care files and `.epochs` handling. Permit exactly these additional directory names, each at one fixed depth:

| Path below `pets/` | Existing stored envelope | New declared capability / required key |
| --- | --- | --- |
| `play/<agentId>.json` | map of canonical positive-safe Telegram user ID string to `PetPlay` | `supportedPetPlaySchemas:[1]` / `petPlaySchema:1` |
| `growth/<agentId>.json` | exactly `{agentId,lit}`; the existing wrapper has **no v field** | `supportedPetGrowthSchemas:[1]` / `petGrowthSchema:1` |
| `checkins/<userId>.json` | one `PetCheckinRecord`, including `v:1` and matching userId | `supportedPetCheckinSchemas:[1]` / `petCheckinSchema:1` |

Require the corresponding capability whenever its directory exists, even empty, all records disabled, or records erased. Do not infer that `supportedPetCareSchemas:[1]` includes these stores. Absent directories add no requirement. Capabilities follow existing supported-version-array rules: missing, null, malformed, duplicate, unsupported version and insufficient arrays refuse. Build manifests already spread `ADAPTIVE_RELEASE_CAPABILITIES`; no independent build-script capability list is needed.

Agent filenames use an absolute-end ASCII `[A-Za-z0-9_-]{1,128}` match plus `.json`. User filenames/map keys are canonical decimal positive safe integers (no leading zeros, negative zero, unsafe round-trip or newline suffix); identity fields equal their path/map identity. No arbitrary directory recursion, nested folders, alternate filenames or Firestore wrappers are admitted.

## Locks, epochs, bounds and rollback

All writers use `petFileSerial(petsRoot)` with the shared `.writer.lock`; play/care rotate the shared `.epochs/<userId>.json`, and check-ins compare that epoch. Reader admission must preserve all epochs and never create/rotate/reset them. Keep existing epoch validation and capability behavior. Refuse a root writer lock before scanning and recheck it after scanning. Any lock, `.tmp`, unknown entry, nested directory, symlink/hardlink, damaged/unknown field/version, nonregular file or changed file discovered by the existing safe-read helper refuses admission; do not clean up or auto-recover it. Verify recognized paths are actual directories and revalidate scanned root/subdirectory identity at completion, so replacing a known directory does not turn a scan into permission to ignore its contents. This does not claim transactional snapshot isolation; installation still needs its separately guarded writer-stop/current-state procedure.

Retain the existing700000-byte per-file ceiling,64MiB aggregate read budget and10000-entry pet enumeration limit. Charge root directories, every recognized subdirectory entry, root care files and epoch files against one shared bounded pet counter; no per-child reset that multiplies the limit. Arrays/catalogues and check-in agent count have the finite caps above. No larger live budget is approved. Oversized state remains unavailable rather than being truncated.

Freeze and execute an actual prior helper as the rollback oracle: both current ca41 helper and the already preserved installed-prior helper reject these directory names before parsing payload. A test that merely removes one capability from the repaired helper is insufficient. Compatible repaired code must preserve these directories and all previous ARC1/care/epoch capabilities. No rollback strips records, resets epochs, enables check-ins or removes a directory to satisfy an ignorant reader. An empty existing directory still blocks such a downgrade. A compatible forward repair is the operational fallback.
