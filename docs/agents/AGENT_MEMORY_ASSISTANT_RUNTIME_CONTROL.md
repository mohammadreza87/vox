## 2. Canonical ARC1 shape

One optional top-level `assistantDeliveryControl` extension is admitted on original canonical FILE schema1 only, behind the permanent content-free format marker in section7. Managed FILE/schema2/3, indexed, Firestore, memory and aliases that merely expose similar methods are unsupported for ARC1 writes. Existing document variants continue reading existing accounts; no automatic conversion. Strict nested unknown-field rejection, bounded safe integers with negative zero rejected, ADP1 opaque IDs/UUIDv4/hex rules and ADP1 state canonical decode apply. The outer optional field is never stripped by normalization, storedForm, old-cohort compatibility or an unrelated writer.

The exact version1 extension is:

- `{version:1, policyVersion:'arc1-control-7d-v1', revision, observedAt, noReplayBefore, sourceFenceSequence, historyEpoch, deletionEpoch, streams, effects}`.
- `revision`, `sourceFenceSequence`, `historyEpoch`, `deletionEpoch` are nonnegative safe counters; `observedAt` is a nondecreasing trusted server clock floor; `noReplayBefore <= observedAt` is a monotonic original-source-time barrier.
- A stream is exactly `{botId, destinationChatId, agentId, space, containerId, messageFloor, highMessageId, lastAcceptedAt}`. Maximum4 unique `(botId,destinationChatId)` streams. Private destination is positive and must equal the Telegram ID encoded by canonical accountId. PersonId is canonical account.personId; containerId is recomputed with containerIdFor. Route agent/space/container is immutable for this stream until its safe idle retirement. Endpoint/credential/key revisions never change stream identity.
- An effect row is exactly `{state, retainUntil}`. `state` is a strict ADP1 DeliveryState, at most4096 canonical encoded bytes; this stricter ARC1 subset can refuse an otherwise valid ADP1 state. `retainUntil = state.createdAt + 7*86400_000`, checked safe. Maximum32 rows/account, unique initialEffectKey, one initial attempt/key. Every row's bot/chat must name a stream; full scope must match canonical account/person and that stream route. Generated/sending rows have no receipt; known results retain only ADP1 minimized receipt/outcome. No free payload/diagnostic field exists.

`effects` is finite detail; stream route/floors and the account barrier are relationship-life safety controls. Their lifetime is explicit and is not misdescribed as a7-day record policy. They remain while the partition can accept/recover effects. Whole-account erasure or safe90-day stream retirement below can remove identifying stream metadata. The scalar account barrier/version remain until account erasure and are included in export as personal/control data.

## 3. Identity, bootstrap and replay

Account resolution is deterministic from authenticated private destination: `telegram-account:<chatId>`. Never accept an arbitrary account from persona/client input. Binding projector must find exactly one current Studio agent for botId and the expected private owner relationship; ambiguous bot routing fails closed. Canonical scope and committed Studio bot/endpoint/credential projections are checked separately. Bot replacement is a new stream and requires fresh current admission; it cannot import old grants.

Initialize only an already-existing, verified canonical account, through an explicit internal adapter call. Persist `noReplayBefore=observedAt=trustedNow` before admitting any source; no historical backfill. The initializer is absent from production composition in this slice. Repeated initialize cannot reset controls, lower a floor, move a route or clear effects. Account recreation after actual full erasure must bootstrap a fresh barrier before any claim. Missing/corrupt/unsupported control state is not an empty active ledger.

Ingress input comes from the future authenticated bot adapter, not a request body. This increment qualifies it only with synthetic server fixtures. Require own private human `chat.id===from.id`, expected bot identity, original `message.date` converted from safe integer seconds to safe milliseconds, and initial plain text type. Store no ingress text. `occurredAt` is that immutable original date, never edit_date, acceptedAt, replay time or a fresh random UUID. Require `noReplayBefore < occurredAt <= trustedNow`, and source initial messageId strictly above stream.messageFloor. Same-second messages at/below the initialization barrier are conservatively refused. Stream highMessageId never decreases; source revisions and sourceFenceSequence are server-assigned under the account lock.

Telegram update_id is correlation only, not durable chronology: the [official Update contract](https://core.telegram.org/bots/api#update), checked26 October2026, says a new ID can be random after a week without updates. Lower/random update IDs do not lower any ARC1 floor or create another identity. Initial effect identity remains ADP1's bot/chat/message/initial/primary-text key. Replayed input with new update ID, attempt/generation UUID, endpoint, credential, key, epoch or scope cannot allocate a second attempt.

Delayed/out-of-order initial sources above all floors can be admitted while capacity remains, even below highMessageId; detailed-key duplicate detection still applies. Sources at/below either floor return fixed `replay_fenced`; a route mismatch returns `route_conflict`; they are not labeled processed/delivered. Message-ID reset/reuse within the same bot/chat stream is conservatively refused; no inferred provider reset or automatic floor lowering exists. A separately reviewed rebinding procedure is needed if those refusals make a stream unusable.

## 4. Finite retention, capacity and pruning

Detail TTL is7days from creation, never refreshed by phase, late result, restart or update replay. No capacity-driven eviction of unexpired rows, especially unknown/sending. A full32-row ledger refuses new claims with `capacity`; it does not displace uncertain effects. A stream limit refuses the fifth active stream.

Prune under the same canonical transaction before admitting work or explicitly through the adapter. Before dropping an expired effect, atomically advance its stream.messageFloor to max(current floor, retired source.messageId). Invalidate content and pre-dispatch eligibility of every surviving row at/below the new floor. Effects already dispatched may still record same-attempt truth. An expired generated row is not a future opportunity; a sending/unknown row expires behind the same irreversible fence. If a late callback arrives after detail pruning, return `metadata_expired`; never recreate the effect, claim failure or send again.

A stream idle for90days (`trustedNow-lastAcceptedAt >= 90*86400_000`, safe arithmetic) can retire only after its detail rows expire/prune. Before deleting the stream, advance account.noReplayBefore to trustedNow and account.sourceFenceSequence. Invalidate every surviving claim whose original occurredAt is at/below that barrier across all streams. This permits removing old bot/agent/chat-route identifiers without reviving old sources. Do not update lastAcceptedAt on duplicate/refused/late-result activity. Fresh post-retirement stream creation still requires original source date above the account barrier and current binding. Every purge is all-or-nothing with its floor write.

Reserve **160KiB (163840 bytes)** for the complete property wrapper and worst future ARC1 ledger once the extension exists, even empty/disabled. With32 states at4096 bytes,32 row wrappers and4 bounded streams, this includes counter/receipt/invalidation growth; schema enforces the entire wrapper<=163840 and requires the fixed future-terminal projection to fit each4096 state slot before claim. The state projection retains all immutable fields/evidence and uses MAX_SAFE_INTEGER for mutable revision/lastTransitionAt, invalidatedAtFenceSequence and outcome.observedAt; contentEligible=false; phase='sent'; reason='provider_accepted'; receipt has maximum safe messageId/botId/destinationChatId, floor(MAX_SAFE_INTEGER/1000) providerDateSeconds, and the longest textEvidence ('matches-submitted'). Compare this encoding with the longest unknown-reason encoding and cancelled/failed projections; reserve the maximum, never just the current generated bytes. Numeric receipt bot/chat identity remains the actual values in stored truth; maximum substitutions exist only in the capacity calculation. ARC1 counters/historyEpoch/deletionEpoch/timestamps and stream integers similarly reserve maximum decimal width. Counter exhaustion refuses new work and never wraps or clears controls. Any exhausted ARC1/account counter makes all dispatch/content eligibility fail closed, even when prior equal stamps exist. Capacity reservation covers terminal proof/invalidation growth; no new claim may consume the last required terminal transition counter. Irrecoverable exhausted controls require a separate owner erasure/recovery operation; they never authorize a reset or send.

The canonical700000-byte ceiling, product-pause reservation and rights-hold future-release reserve are unchanged. Every canonical writer with ARC1 present must validate a capacity-only projection in which ARC1 consumes the full163840-byte block, including decimal counter growth to MAX_SAFE_INTEGER, while existing product-pause and rights-hold future-release checks are evaluated together. A fixed-size opaque padding surrogate is permitted only inside this byte calculation and is never stored or schema-admitted. Tests must prove exact future projection byte equality; checking only current serialized size is insufficient. No claim is committed unless generated→sending→maximal terminal result/invalidation remains representable with those rights reserves. This reservation can reduce admission capacity; it never raises account limits.

## 5. Transaction and current-source authority

All ARC1 mutation APIs use actual FileAdaptiveStorage/AdaptiveRepository transactions, never a turn-read-scope draft as committed proof. The adapter requires the concrete original FILE kind, committed read, write fence and existing account. Committed Studio binding is an injected trusted server projector for synthetic qualification; it is not sourced from model output or caller-supplied equal authority objects. The real projector/ingress composition is a later activation gate.

The adapter computes canonical authority fingerprints from account binding, core/purpose policy, grants, epochs and current committed Studio route/credential binding. Before `claim`, the adapter itself exposes `prepare({authenticatedIngress, generatedText, decoratedText, generationId, attemptId})`: it samples the trusted constructor clock, loads the actual initialized committed account/Studio projections, resolves the server-selected keyId/key, and invokes ADP1 preparation transiently. No caller supplies authoritative scope, source revisions or ADP1 authority. It emits a transient prepared object; no source-text or prepared object is stored. The future authenticated-ingress producer remains responsible for authenticity of the ingress assertion; this increment proves canonical/control enforcement against synthetic trusted ingress, not a real authenticated poller.

For initial-only ARC1, ADP1 source.revision is exactly0 (server-assigned initial revision), acceptedAt=trusted preparation time, occurredAt=original provider date, updateId=correlation. There is no pre-preparation source allocator or later edited-source generation. `claim(prepared, authenticatedIngress)` compares original bot/chat/message/date/update assertion and recomputes canonical projection; preparation/claim race fails stale rather than inventing revision. authorityRevision is SHA256 of the fixed ordered tuple ['arc1-authority', accountId, personId, binding, coreFingerprint, purposeFingerprints(personalization,auto_memory), committedStudioBinding]; grantRevision is SHA256 of ['arc1-grant', matching canonical agentGrant rows ordered by revision, permission epochs/revisions]. sourceFenceRevision is SHA256 of ['arc1-source', accountId, sourceFenceSequence, noReplayBefore, stream.messageFloor], with0 for a not-yet-created stream; sourceFenceSequence is the actual canonical counter. historyEpoch/deletionEpoch are the distinct canonical ARC1 counters, initially0; they never read or revive legacy Tireh history. A forget/erasure raises them and sourceFenceSequence. expiresAt is the minimum current binding/core/purpose policy deadline. ADP1 claim expiry is min(that deadline, preparationNow+60000). Every hash is an integrity stamp of actually loaded committed controls, not a replacement for the underlying checks. The initial slice requires current core_text and the same optional.personalization and optional.auto_memory permissions as archive retention; it does not infer that receipt retention has a legal basis from those flags. Strict current-policy denial means no new claim or dispatch. Current authority, finite preparation deadline and exact effect/revision/attempt/body evidence are separate comparisons.

APIs (names can be idiomatic; semantics cannot vary):

1. `initialize(owner, trustedBinding)` persists the fresh barrier only; no send capability.
2. `claim(prepared)` revalidates ADP1 prepared integrity using the server key resolver, full derived scope/binding/source and its original canonical source revision/fence; prunes safely, freezes the unique route and commits generated state with future capacity. Duplicate same key returns only fixed `already_claimed` with its metadata status; it never returns a fresh dispatch marker. A changed route/attempt/generation/full immutable claim returns fixed conflict, without disclosing another route's record. Claim must not rely on supplied ADP1 authority equality alone.
3. `beginDispatch(expectedClaim, prepared)` validates current committed canonical/Studio source authority, then CAS transitions exact generated claim to sending. The returned marker does not authorize a future HTTP by itself.
4. `isDispatchCurrent(expectedClaim, prepared)` is synchronous, reads only genuinely committed account+Studio projections, refuses busy/missing/stale/unsupported, validates exact sending revision/attempt/evidence, current source floors/fence, current authority and deadline. It never consults a mutation draft. A later dedicated no-retry transport must call this at its actual POST invocation with no await/intervening work. This slice uses synthetic callbacks only and makes no real final-HTTP-fence claim.
5. `recordResponse`/`recordUncertainty` CAS the original sending/unknown attempt with ADP1 response reclassification; callback cannot replace attempt or inject an unbound normalized receipt. Late accepted receipt after source/permission invalidation may preserve truthful `sent` metadata with contentEligible=false, even though current content authority denies. It never reenables content, permission or history. Conflicting terminal facts fail; exact duplicate is idempotent. Result commit failure leaves durable sending/unknown; no retry permission follows.
6. `recover` turns abandoned sending into ADP1 unknown without effect invocation, and closes expired generated state. A sending claim is never resumed or retried after restart.
7. `invalidateSource(bot,chat,messageId)` operates even with archive unavailable/unenrolled. Every invalidation of a known stream advances stream.messageFloor to at least target messageId and account.sourceFenceSequence, then invalidates affected known/lower claims. Thus deleting the detail later cannot permit a replacement initial effect. If no matching stream exists (including stream-capacity refusal), do not silently return or allocate a fifth route: advance account.noReplayBefore to trustedNow and sourceFenceSequence, invalidating all surviving pre-floor claims. Unknown/out-of-order edits consequently lose some delayed sources conservatively. Edits never allocate an effect or refresh original date. Duplicate invalidations are monotonic/idempotent. `invalidateScope` handles forget/revoke/clear using a monotonic fence and contentEligible=false, preserving original effect identity/truth and route/floors. This source adapter is callable but unwired; this increment does not claim live edits already reach it.
8. `exportOwner` returns strict metadata plus honest coverage/expiry controls only after canonical owner/current export authority. Mandatory `AdaptiveLifecycleService.buildAccountExport` integration projects only streams/effects in the authenticated owner's selected space; an optional assistantDeliveryControl object includes version/policy, the account-wide noReplayBefore/sourceFenceSequence/historyEpoch/deletionEpoch barriers (labeled account-wide), selected-space stream routes/floors, and selected-space effect metadata/retainUntil. It never includes other-space route/receipt/evidence, keys or content. Use existing final export revision/deadline fence, additionally bounded by the earliest exported row retainUntil. The lifecycle sweep prunes ARC1 under the same authoritative transaction even when feature flags are off. No separate account scan or export file is created. It cannot enumerate another person's accounts or return keys. `eraseScope` immediately removes HMAC evidence/receipt detail by fencing then dropping affected rows, preserving route/floors/account barrier needed to deny replay. Such dropped rows cannot later record detail; late callback returns metadata_expired. Before destructive detail erasure, any known sent/unknown summary returned to the owner must not claim never-sent. Whole-account erasure removes the extension only with all ingress disabled; next reconstruction must use fresh initialization, never restore a prior archive/backup as authority.

A source-fence change is account-conservative: it may deny otherwise valid pending claims in another route, which must be reported as fenced/cancelled coverage, never silently sent. Result truth recording uses the immutable original ADP1 claim plus current invalidation sequence and does not require revival of the original grants.

General account writers may preserve or monotonically strengthen ARC1 controls only.
