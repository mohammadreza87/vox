## 2. Qualified time is an admitted capability

The current `clock?:()=>number` injection is a low-level seam, not proof of UTC. Define a shared server-side `QualifiedMemoryTime` capability registered by the actual runtime/maintenance composition, bound to canonical root identity, FRO1 owner epoch, process generation, artifact identity and approved time-policy digest. Copied objects/functions, file contents, caller fields and env booleans cannot mint it. Loss/drain/revocation expires it. Every actual synchronous clock call revalidates current owner and permit; checking only at boot is insufficient.

The concrete provider interface is:

```ts
type TimeRequest = { version: 1; nonce: string; rootBinding: string;
  artifactDigest: string; policyDigest: string; purpose: 'initialize'|'resume'|'runtime' };
type UtcAssertion = { version: 1; requestDigest: string; providerId: string;
  keyId: string; utcMs: number; uncertaintyMs: number; sequence: number;
  issuedAtMs: number; expiresAtMs: number; signature: string };
interface QualifiedUtcProvider {
  acquire(request: TimeRequest, signal: AbortSignal): Promise<UtcAssertion>;
}
interface QualifiedMemoryTime {
  sampleNow(): { nowMs: number; utcLowerMs: number; utcUpperMs: number };
  assertCurrent(): void; // synchronous; no network, no user callback
}
```

The provider request is a new external metadata flow: `rootBinding` is fresh random opaque per-acquisition material, mapped to actual root/owner only in local transient state; it is never a path, inode, stable root digest, process/account ID or erased-owner identifier. The provider sees only fresh nonce/binding, artifact/policy digests and fixed purpose. Its independently approved request/log retention, access, regional handling and cost policy is a production gate; do not forward the operation record or raw root metadata. Provider calls require the separately authorized qualification/operating scope, and no call occurs in this documentation task. All schemas are strict/versioned; integers are safe nonnegative (no negative zero), nonce/digests are 64 lowercase hex, identity/key IDs are bounded approved identifiers, signature encoding/size/algorithm is fixed by the approved provider policy, and the whole assertion is at most 4,096 bytes. This reuses the existing bounded control-message size to prevent arbitrary provider responses becoming a metadata channel; it is a proposed engineering ceiling, not observed provider compatibility. Reject unknown fields/keys/algorithm, duplicate/out-of-order sequence, wrong nonce/request/artifact/root/purpose/policy, invalid signature and expired/revoked assertion. Raw assertion/signature never enters logs, owner exports or operation records. Trust-policy/signing-key custody and revocation authority must be independently governed; a key mutable alongside the data-root controls cannot certify independent current time.

A locally pinned, operator-approved policy fixes provider identity/endpoint, algorithm, trust roots, key validity/rotation/revocation and independent evidence of UTC accuracy; maximum uncertainty, request elapsed time, assertion lifetime, monotonic extrapolation age and oscillator drift; accepted host/boot clock behavior; and authenticated original-source timestamp behavior. These are required numeric policy values, **currently unknown**, not defaults the implementer may guess. No provider or signing key is assumed available. Signature alone authenticates a speaker, not the truth of its clock. A provider deriving its assertion only from this host's wall time/high-water is not independent evidence. TLS, a clock file, NTP configuration, `Date.now`, monotonic elapsed time and a local signature do not by themselves qualify this interface.

`acquire` occurs outside final FILE/effect critical sections with an approved finite timeout and cancellation. Verification binds the request and monotonic send/receive interval. The admitted sample carries a conservative UTC interval, including measured request delay, attested error and permitted extrapolation drift. `sampleNow` advances that interval using the qualified monotonic clock only for the policy's bounded age, rejects regression/suspend/host-boot mismatch or invalid permit, and returns **`nowMs = utcUpperMs`**. Use that conservative upper bound for stored acceptance/high-water and expiry/deadline tests, so uncertain time cannot extend authorization. Store neither the interval nor a permit in per-owner state. An expired adapter refuses until an independently validated fresh assertion is admitted; no request is retried merely to salvage an expired action.

The existing scalar consumers must also receive the qualified interval checks appropriate to them: manager authentication requires `utcUpperMs < auth_date*1000 + 300000` and `auth_date*1000 <= utcLowerMs + 2000`, in addition to current HMAC/Ed25519 checks. A future-time check against only the upper bound would conceal UTC uncertainty. The original-source future check likewise requires `originalDateMs <= utcLowerMs + 2000`; do not reuse `nowMs+2000` alone. Every not-before/quarantine barrier, including eventual ER1 physical cleanup, requires `utcLowerMs` strictly past the applicable floor; an upper bound cannot prove that time has passed. This requires explicit interval-aware auth/source/not-before/final-fence API changes around the existing scalar interfaces, with a versioned adapter consumed on the actual paths; the present scalar-only composition is insufficient. A final sample must still satisfy the existing synchronous wall/monotonic and actual durable-high-water checks. New provider observations whose upper bound is below the actual high-water refuse; never edit the file downward or return a cached older sample.

Independent **source-creation** evidence must establish ER1's positive bound S=2,000ms and Q=1,000ms against admitted UTC intervals, including delayed/unreceived sources. Arrival-time validation cannot establish it. The policy must also supply an independently evidenced negative source-skew bound for readiness; none is assumed here. Preserve ER1's `ceil((t0+S+Q)/Q)*Q` cutoff and strict `originalDateMs > cutoff`, including equality/same-second refusal and no `edit_date` substitution. With interval uncertainty, t0 is the conservative admitted upper sample at locked confirmation acceptance; this can delay eligibility and never weakens ER1's floor. `Ready / Send a new message` additionally requires the qualified lower UTC bound minus the admitted negative source skew to reach at least the next whole quantum after the floor, and current core/reply eligibility. Until that evidence exists show `Fresh start confirmed; message readiness is pending`. No fixed waiting promise or Telegram notification is added.

Operational MI1 time qualification and actual protective-bootstrap qualification are prerequisites to **production first marking**. Provider-source skew, modern real-client signature delivery and applicable bootstrap behavior cannot be waived by substituting a test clock. Synthetic-only policy fixtures are explicitly scoped to synthetic roots and cannot be loaded for production.

## 6. Restoration, restart and rollback semantics

The supported restoration is **current-authority reconciliation with zero payload import**, through the existing lifecycle service, under freshly authenticated owner and current work/role authority. Require intact current account, exact captured incarnation/revision and strict pair/high-water; final committed recheck follows waits and export projection. Compare bounded old rows only to matching current content/revision/expiry and report accepted-current IDs/suppressed IDs with `importedPayloads:0`. Do not persist an imported snapshot, consent/grant, binding, ARC row/effect, archive locator, cutoff or source text. A replacement incarnation refuses even if account ID, row IDs or revision counters match. For a legacy snapshot without incarnation, it may only identify current matching rows within this zero-import operation when the server captured the current lifecycle independently; it cannot assert incarnation continuity. Unknown lineage is excluded from context/extraction.
