## 1. Wrapper witness covers startup failure

Use the existing private runtime-process-v1 receipt, with strict bounded canonical state unions and one operation-bound UUIDv4 spawnId. Immutable base binds wrapper identity, expected root identity, release tuple/artifact identity and current operation digest when a managed operation exists. Write/fsync a `starting` receipt before spawn; childPid and holder are null until actually observed. After the actual ChildProcess `spawn` event, its PID may be recorded in the next starting revision. Each successor includes previousDigest of the exact preceding bytes and a strictly increasing revision. The operation captures that receipt/expected spawn before startup/stop decisions; unknown stale records are never overwritten.

`running` requires the same actual child object/PID and fully validated acquired guard/root/release; only then add exact holder identity/digest/nonce and allow readiness. Holder fields are never invented from PID. Actual child `exit` emits/fsyncs `exited` from either starting or running before wrapper process.exit, retaining immutable spawn/release/root/known-holder fields. `exited` may honestly have holder=null if no valid holder was ever observed. This proves child termination, not successful startup. A spawn `error` before any child was created emits distinct `spawn_failed` from that actual event; never fabricate running or an exit event. Both terminal shapes use closed error/signal/code metadata only, no exception/body/environment.

The stopped controller accepts only a matching revision/digest chain, unloaded supervisor, original child/descendants gone, listener closed and unchanged root/current. If failure occurred before a holder existed, cleanup is allowed only when the expected guard was absent and remains absent: there is no holder to unlink. A newly appearing, partial, malformed or uncaptured guard means HOLD, even if the recorded child exited. If a known valid holder existed, only its exact stopped identity may be removed. No timeout, ESRCH, PID comparison or inferred no-holder substitutes for those checks. No retry/restart is automatic. Interrupted receipt publication or wrapper death without a matching terminal witness remains fail-stopped.

The lifecycle receipt parser/CAS/writer is release-owned in studio-production.mjs; architect-owned shared utility supplies strict owner snapshots and retireStopped/releaseMaintenance APIs, without inventing OS exit proof. QA freezes transitions for spawn-error, exit-before-owner, exit-after-partial-owner, exit-before-running-receipt, normal running exit, missing/changed receipt, new foreign guard and supervisor restart. Starting is not readiness or effect authority.

## 2. Precise macOS first-f895 identity adapter

**Choose one tiny read-only C helper, not a new npm/native-lock package or platform abstraction.** Proposed new owned source path (requires root assignment): `scripts/native/studio-process-metadata-darwin.c`. Build output `.next/studio-process-metadata` compiled after Next completes and before final provenance manifest publication; installed sibling `studio-process-metadata` at release root. Current target is darwin-arm64; the legacy live migration adapter is explicitly macOS-only. Linux CI can qualify portable owner/wrapper logic and refusal on an unsupported legacy adapter; it must not pretend to qualify libproc or first macOS migration.

The local Apple Command Line Tools SDK declares the necessary public interfaces; this was verified by header reads only:

- `proc_pidinfo(pid, PROC_PIDTBSDINFO, ...)`: UID, PPID, process group, PID and start seconds/microseconds.
- `proc_pid_rusage(pid, RUSAGE_INFO_V0, ...)`: `ri_proc_start_abstime`, a uint64 kernel start timestamp. Use it together with BSD start sec/usec, not second-resolution ps text. Serialize all uint64 values as decimal strings, never rounded JavaScript numbers.
- `proc_pidpath`: actual executable path; `PROC_PIDVNODEPATHINFO`: cwd path/vnode identity. Do not use comm/name/title as identity and do not read process environment or argv memory.

ABI1: one strict positive decimal PID argument, reject PID 0/negative/extra/overflow inputs. Fixed JSON output (maximum 16 KiB) reports version/status, PID/PPID/UID/process-group, startAbsTicks/startSeconds/startMicroseconds strings, executable and cwd identity/path, plus bounded direct-child/process-group PID arrays using proc_listchildpids/proc_listpgrppids (maximum 64 each, overflow refuses). No arbitrary memory, environment, argv or open-file listing API. Query birth before and after all other fields and require identical identity/parent/UID; changed/short/error/permission-denied observations return closed `changed|absent|unavailable|invalid`, never partial success. Parent parser validates exact keys/types/lengths, enforces expected UID, compares known paths in memory and emits only match booleans/digests/reason codes in release receipts. Raw unrelated paths/output/errors are not logged. No privilege elevation or helper-side signal/removal operation exists.

Proposed exact Darwin build command, to be frozen with source/compiler/SDK/architecture identities under later build authorization:

```sh
xcrun --sdk macosx clang -std=c11 -O2 -Wall -Wextra -Werror \
  -arch arm64 -mmacosx-version-min=11.0 \
  scripts/native/studio-process-metadata-darwin.c -lproc \
  -o .next/studio-process-metadata
```

This command was not run. Link dependencies are only system libproc/libc; no additional package install. Independent qualification must freeze actual C source hash, compiler executable/version/SDK/deployment target, produced Mach-O hash/mode/architecture and synthetic native output. The declared SDK headers include `libproc.h`, `sys/proc_info.h` and `sys/resource.h`; no unexposed PROC_PIDUNIQIDENTIFIERINFO extension is assumed. Any missing API/insufficient returned structure is a concrete unsupported-host HOLD, not a ps/PID fallback.
