# Isolated read runners: source and fixture operations

**Status, 20 October 2026:** the candidate described below is committed and merged into `develop`; the "uncommitted" wording is historical.

CONN-024/025 bounded read slice, 19 October 2026. Source starts at `d8d6766`, with an uncommitted candidate requiring independent diff review. Browser and server diagnostics appear as separate code-owned provider profiles. They remain `disabled_pending_qualification`; neither cloud access nor an API connection confers worker authority.

`browser.page.read` accepts one registered `targetId`. The server resolves its exact public HTTPS URL, checks every DNS answer, pins the socket and bounds one HTML response. Redirects, compressed content, non-HTML, private/transition addresses and content over 128KB fail closed. No cookies or authorization header are sent. The worker renders that snapshot in a fresh Chromium context with `chromiumSandbox:true`, JavaScript disabled, request routing aborted, downloads blocked, popup/dialog closure and a no-source CSP. The container has `--network none`, so a route-hook bypass still cannot create external network access. Outputs are bounded title and visible text plus explicit `offline`, `javascript:false`, `interactive:false` flags; no DOM, storage, credentials, screenshots or browser session is returned. This is a public-page read path. Authenticated login/session handoff and interactive actions are unavailable.

`ssh.service.status` accepts only registered opaque host/service IDs. Server inventory supplies a literal IP/port, unprivileged user, Ed25519/ECDSA public host key and independently verified SHA256 fingerprint. The worker uses fixed OpenSSH arguments, no personal config, host identity strict checking, explicit transient key/known-host files, no SSH agent, no forwarding, no password/KBI and no arbitrary command. It invokes only `vox-runbook-v1`. Its TCP bytes cross a bounded stdio tunnel; the orchestrator connects to the inventory's exact literal IP. The SSH container also has no network. The remote root-owned forced-command program accepts a bounded typed request and runs only fixed `systemctl show` properties for a root-owned service inventory. Raw SSH stdout/stderr never becomes a model result. No privileged write, shell, upload, host lifecycle or deployment runbook is implemented.

`RunnerPolicy.assertCurrent` must query the durable current broker operation/grant/identity/epoch, with exact resources. It runs before I/O, immediately before worker dispatch, and before any result becomes visible. `ConfiguredRunnerExecutor` additionally binds the operation and Work/Personal space. ProviderRegistry routes only the two finite tool names to this configured executor; no executor is supplied by default. The deployment must provide an independently admitted worker/service enrollment channel and per-person/space/connection inventory. Declared labels, a token string or an instruction are not proof of that identity. Static OAuth token enrollment does not admit runners.

## Worker build and isolation

Build only the dedicated image in `services/connections-runner/`. Its base is the official Playwright 1.64.0 Noble manifest `sha256:06a9939e57531807f8d5fd76ce44b53165ffb7d7501d87ab10e285c20b1e971f`; `playwright-core` is pinned to 1.64.0. Record the resulting immutable local image ID or deployed digest. `DockerRunnerSandbox` rejects floating tags and uses `--pull never` at execution. The orchestrator's Docker socket is never mounted in a worker.

Each operation gets a named disposable container, UID/GID10001, read-only root filesystem, all capabilities dropped, `no-new-privileges`, 128 PIDs, one CPU, 768MiB RAM, bounded shared memory, 192MiB noexec/nosuid/nodev tmpfs, output/traffic ceilings and a 20-second kill deadline. No host directory, browser profile, developer key, agent socket or port is mounted/exposed. The browser uses a debugging pipe inside the container, with no DevTools listener. The orchestrator explicitly removes the container after every result, failure or cancellation; cancel does not assert a remote SSH process stopped. The implemented SSH operation is read-only, and future effects need remote durable request-status reconciliation.

The seccomp source is Playwright v1.64.0's profile, plus one explicit `chroot` syscall allow needed by Chromium's user-namespace sandbox. Without it, a cap-drop-ALL smoke failed `sys_chroot("/proc/self/fdinfo/") == 0`. The additional syscall does not add container capabilities or disable Chromium's sandbox. The reviewed profile SHA256 is `513c31efdc06215e0c5c84cc60cbef110ea619962df9e78d62a68633094cbeab`; the orchestrator rejects changed bytes. The final sandbox/IAM/kernel admission still belongs to independent security review.

## Remote SSH installation requirements

On an explicitly authorized disposable test host, create a dedicated unprivileged principal with a root-owned, non-writable home and no ambient credentials. Install `remote-runbook.mjs` root-owned at `/usr/local/libexec/vox-runbook`; place the root-owned immutable service-ID-to-unit mapping at `/etc/vox-runner/services.json`. Configure authorized_keys with `restrict,command="/usr/local/libexec/vox-runbook"`; disable user RC/environment, forwarding and PTY at sshd level. Independently verify the server's public host key over a trusted channel, then register its fingerprint and literal target IP. Never learn or replace a key through TOFU, and never test against the existing Mac Studio production host incidentally.

The remote reader limits stdin while reading (1000 bytes and five seconds), validates the exact request keys and operation, executes `systemctl` without a shell under a five-second/output limit, and returns only service ID/active/substate. The unit mapping and installation permissions require target verification before admission. Host-key mismatch fails before authentication/command execution. The source does not configure or test a real host automatically.

## Signed service identity source completion

The guarded source now wires `loadRunnerAdmissionRegistry` into optional broker bootstrap and `operatorEnrollRunner` into the existing pending/claim flow.
