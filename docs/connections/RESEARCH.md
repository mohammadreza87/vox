# Connections research and provider qualification

Checked 19 October 2026. Primary documentation and local source inspection; no provider login, app registration, customer-data read, paid API call or server probe was performed. Availability below means documented capability, not entitlement for Joyixir or a successful Vox integration. Recheck endpoints, protocols, scopes, terms and pricing when each connector is implemented.

## What the research changes

Official MCP is useful but is not a substitute for scoped product authorization. Providers differ in client registration, resource granularity, action coverage and protocol version. Prefer a small task-oriented tool surface with explicit outcomes over exposing an entire upstream API. This fits current Cloudflare guidance on narrow MCP tools, scoped permissions and evals; using that guidance does not require moving Vox to Cloudflare Workers. [Cloudflare MCP guidance](https://developers.cloudflare.com/agents/model-context-protocol/).

The latest protocol is materially different from older deployed integrations. [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28) is a reference for qualification, while individual providers may require older initialization/session behavior. Record exact protocol, SDK/package digest, auth method, tool schema hash and server compatibility evidence. Do not copy `@latest` examples into production deployment manifests. See [architecture](ARCHITECTURE.md) for the proposed transport profiles.

## Provider matrix

The final column is a proposed Vox capability, not a claim that the provider implements Vox's permission model. Narrow resources at the provider where possible and enforce the residual restriction in the trusted broker before model exposure. If a tool's result cannot be reliably scoped, exclude it or choose a qualified API adapter.

## Gamend evidence and reuse boundary

Read-only inspection at local revision `31e3a2887531cc4e046b62af238acd0b98b8f611` found:

- [MCP controller](/Volumes/Workspace/Ludaxis/gamend/apps/api/src/modules/agent/agent-mcp.controller.ts): `/v1/mcp`, `gamend_context`, `gamend_discover`, `gamend_describe`, `gamend_preview`, `gamend_execute`, `gamend_status` and operation schemas.
- [Program contract](/Volumes/Workspace/Ludaxis/gamend/docs/product/agent-platform/PRD.md): domain coverage and metric/tenant restrictions.

The integration task should discover the **currently deployed** admitted version and permissions through an authorized test account, map those into Vox's stricter grant/destination model, then test protocol and receipts. Broad `gamend_execute` must be decomposed/validated by named operation policy before it is offered to an agent. No arbitrary operation ID, tenant substitution, raw credential result or release action is authorized by merely installing this connector. Source and dated project-state documents were not used to certify live service status.

## Connector admission record

Every provider task produces one versioned record containing: official source/retrieval date; supported auth and protocol profile; app registration/account eligibility; requested/granted scopes; resource selector semantics; operation-to-permission map; owner/service identity; processors/regions/retention review; rate limits; result schema and source IDs; idempotency/receipt/reconciliation behavior; revoke/delete behavior; network allowlist; package/schema hashes; fixture and real-account evidence; exact supported actions; disabled actions and reason. Unknowns remain unknown until tested.

Use three distinct badges internally: **documented**, **fixture-qualified**, **account-qualified**. Production-ready is a separate per-capability release state. A successful `tools/list`, saved token or healthy endpoint alone cannot promote that state.
